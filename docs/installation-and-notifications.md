# 安装与通知

## 需求与验收

设置新增独立的“安装应用”和“推送与通知”分类，外观和离线同步各自保留。任务到期、面试提醒设置沿用原规则；真实账户的工单创建、回复和状态变更形成按接收人隔离的通知。演示/游客身份不创建系统推送订阅。

应用内提醒和账户系统推送投递偏好默认开启，但浏览器权限仍由用户决定。首次进入已配置推送的真实账户时，先解释用途，只有点击按钮后调用浏览器授权；拒绝或点击“稍后”后不会反复弹出，设置页保留恢复指引。锁屏只显示通用更新摘要，不显示工单、面试、岗位或个人资料正文。

通知中心会静默补入已有历史，后续新通知合并为一个顶部摘要，不把每轮轮询或每次刷新得到的旧通知重新弹出。可单独标记已读和收起，历史仍可在设置中分页查看。打开页面时每 30 秒补拉，重新在线/进入前台时补拉；关闭网页后的系统通知取决于浏览器后台推送支持、授权、有效设备订阅及系统调度，不能无条件保证实时送达。

通知点击只接受本站路径。当前页面由应用路由处理，保留未保存编辑确认；没有打开页面时，由 Service Worker 打开本站路径。退出登录会先撤销当前设备的服务端订阅并取消浏览器订阅，保留其他设备；发送前重新核验当前会话、账户状态、工单访问和投递偏好。设备后台只保存当前账户的非敏感 ID，旧账户推送不会展示。

## 发布

先应用增量迁移 `0010_notification_delivery.sql`，再发布既有后端与前端。迁移只增加投递偏好、收起时间、设备会话归属和索引，通知历史不删除。旧设备订阅没有可撤销会话归属，会停用并要求用户在新设置中重新开启。

复用已有 VAPID 配置，不生成、不导出、不重新设置既有私钥。修正旧发送器的接收者 ECDH、HKDF 标签和 Web Crypto 原始签名处理；使用 RFC 8291 公布密文和 RFC 8292 签名 fixture 验证，不发送真实通知。

安装入口复用浏览器一次性 `beforeinstallprompt`，取消后不重复调用过期事件。为既有图标增加 192/512 PNG 和安全区 maskable 图标，以满足常见 Chromium 安装要求。iPhone/iPad 的 Web Push 需要 iOS/iPadOS 16.4 或更高版本及主屏幕 Web App；界面同时给出手动安装指引。

参考：[Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[通知权限](https://developer.mozilla.org/en-US/docs/Web/API/Notification/requestPermission_static)、[WebKit iOS/iPadOS Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)、[RFC 8291](https://www.rfc-editor.org/info/rfc8291/)、[RFC 8292](https://www.rfc-editor.org/info/rfc8292/)

## 发布后真机验收

使用测试账户核验安装接受/取消、首次权限允许/拒绝、重复点击、设置投递失败后的重试、通知读/收起历史、网络恢复只提示新事件、退出后旧账户消息不显示。通过已有任务/面试或工单事件产生测试通知，不为验收自动调用收费 AI。真实系统后台推送需要在已授权、支持的平台上单独验证。
