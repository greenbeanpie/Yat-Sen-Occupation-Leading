# 已保存模型测试与脱敏诊断

- 超级管理员在 AI 配置页主动点击「测试已保存配置」才调用模型；保存、加载和读取日志不调用模型。测试只提交已保存版本和随机请求编号，不提交表单草稿、密钥输入或个人资料
- `POST /api/v1/admin/ai-settings/test` 使用既有目的地绑定和协议适配器，固定非个人短提示；一次请求、不自动重试，不更换模型或思考强度。遵从已保存超时与输出上限（当前上限 60 秒、4096 tokens），响应最多 8192 bytes；每分钟最多3次，全局只允许一项测试同时进行。请求编号24小时内不可重复付费派发
- mock、未配置密钥或损坏配置不伪装真实连接成功。结果只代表连接与基本完整文本响应，不保证 JSON/OCR/全部业务质量。测试超时不代表配置无效，也不阻止保存；测试不会修改配置版本
- 使用 Origin/Fetch-Site/JSON CSRF 检查和服务端非演示超级管理员鉴权；派发前再次验证当前权限与配置版本。返回和错误均 `Cache-Control: no-store`
- `GET /api/v1/admin/ai-settings/logs` 只有超级管理员可读，按倒序序号分页。记录随机请求编号、阶段、耗时、HTTP状态、固定分类、协议/供应商/已知模型ID及本次上限。不记录输入/输出正文、个人资料、密钥、完整header、URL、原始exception/cause或stack。未收录的自定义模型ID使用占位值
- D1 migration `0009_ai_diagnostics.sql` 仅新增日志表。每条UTF-8事件最多2048 bytes；插入与裁剪在同一 D1 batch 事务中，始终同时保留最后最多1000条、事件JSON总计最多1,000,000 UTF-8 bytes。日志故障或超过1秒不替代业务结果
- DNS/TLS/reset/refused分类仅来自标准错误代码或已知运行时提示；没有足够信息时保留 `network_error`。30x重定向记录HTTP状态但不跟随，不把分类推断成某平台的出站限制

本地检查采用假密钥和mock请求，覆盖全部接入协议、非超管/CSRF、重复/并发、版本不升、权限变化、日志双限与故障隔离；没有执行生产收费测试。浏览器和真实模型调用需要用户主动验收。
